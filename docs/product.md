# StockCapy 產品設計

## 這是什麼

一個自用的美股投資判斷工具。核心回答一個問題：**這檔現在該不該進？**

不是報表工具，也不是交易工具。它算出一個價格基準，然後在到價時通知你。

## 要解決的問題

原本的狀況：
- 券商（Firstrade）沒有 API，帳戶資料要手動看網頁
- 合理價要自己查 P/E、自己算，而且每次用的假設都不一樣
- 到價與否要自己盯
- 美股用美元計價，但實際賺賠是台幣，兩者混在一起分不清
- 股利被預扣 30%，實收多少要自己對

## 核心設計原則

### 1. 只給基準，不給建議

工具輸出估值模型的結果與價格位置，**不產生買賣建議**。理由不是免責，而是因為結論高度依賴假設，而假設是使用者的判斷，不是工具的。

具體體現：分析師目標價**永遠不納入**中位數計算，只列作對照。

### 1b. 智慧提醒也只描述規則，不下判斷

多疊一層的「智慧提醒」（技術指標 + 均價規則）看似違反原則 1，其實是它的延伸：規則的門檻由使用者設定並寫死，規則引擎只回報「你設的哪幾條被觸發了」，摘要層（`advisor.py`）只把觸發的條件連數字講成人話，結尾一律帶「非投資建議」。摘要層不呼叫 LLM，用確定性樣板，從結構上就不可能滑進買賣建議（見 decisions.md D12）。上線前用 `signals backtest` 校準門檻，避免門檻設得沒資訊量。

### 2. 不適用就說不適用

四個估值模型各有適用範圍，用錯會產生誤導性的精確數字。所以有**適用性閘門**：

| 模型 | 採計條件 | 為什麼 |
|---|---|---|
| Graham Number | P/E ≤ 25 且淨值 > 0 | 價值股篩選工具，對輕資產/高成長股系統性低估 |
| Target P/E | EPS > 0 | 永遠適用，但結論等於使用者的倍數假設 |
| Gordon Growth (DDM) | 殖利率 ≥ 2% | 僅適用穩定配息股，spread 太小會爆掉 |
| Analyst Consensus | — | 永不納入，只對照 |

ETF 沒有 EPS，四個全不適用，改用 200 日均線當趨勢錨點，並在「依據」欄明確標示 `200MA`——不與內在價值混為一談。

### 3. 分清「不知道」與「算不出來」

行情源（yfinance）是非官方介面，會暫時抓不到資料。早期版本會把抓取失敗顯示成「無可用模型」，跟「這檔真的無法估值」無法區分。

現在分成兩種狀態：`資料不足`（抓取失敗，稍後重試）與 `無`（資料到齊但這檔沒有可用的估值基礎）。

### 4. 假設要有來源，且來源要透明

`target_pe` 這個假設主導整個結論，所以它不能是隨手猜的數字。解析順序：

1. 通用預設（18）
2. **該檔自己近 5 年的歷史 P/E 中位數**
3. 使用者的手動覆寫

而且歷史 P/E 會被**主動拒用**：四分位距超過中位數的 0.8 倍時，代表 EPS 變動太劇烈、trailing P/E 已失去意義，退回預設而非給出假精確的數字。

實例（2026-09）：

| | 現在 P/E | 歷史中位數 | 四分位距 | 採用 |
|---|---|---|---|---|
| MSFT | 28.2 | 35.3 | 32.5–37.8（窄） | ✅ 歷史值 |
| KO | 25.0 | 25.4 | 24.2–27.1（窄） | ✅ 歷史值 |
| NVDA | 26.7 | 73.9 | 46.0–134.3（極寬） | ❌ 退回預設 |

每個畫面都會標示這檔用的是 `歷史P/E` / `手動` / `預設` / `命令列`。

### 5. 台幣報酬率要用成交當天的匯率

用今天的匯率換算成本會把匯率損益混進股票損益。所以每筆交易都標記它**成交當天**的匯率，並把總損益拆成兩塊：

- **股票漲跌** = `(現值美元 − 成本美元) × 今日匯率`
- **匯率變動** = `成本美元 × (今日匯率 − 成本均價匯率)`

兩者精確相加等於台幣總損益（有測試跨多組情境驗證這個等式）。

匯率查詢**絕不使用未來日期**——那會無中生有製造獲利。週末假日回溯到前一個交易日。

### 6. 資料留在本機

SQLite 在本機，`.gitignore` 擋掉 `.env`、`data/`、`*.csv`。對外只呼叫兩個端點：yfinance（行情）與 api.telegram.org（通知）。

認證採 **fail-closed**：未設 API token 時，伺服器拒絕綁定非本機位址。

## 功能分類

| 類別 | 能力 |
|---|---|
| **資料進入** | 券商 CSV 匯入（去重、DRIP、內嵌預扣稅）、手動輸入持倉、成本基礎缺失偵測 |
| **現狀呈現** | 持倉、均價、損益、權重、產業曝險、每日淨值快照 |
| **合理價與入手價** | 四模型 + 適用性閘門、價格位置（P/E、52 週區間、200MA） |
| **假設管理** | 每檔持久化、歷史 P/E 自動推導 + 穩定性閘門、來源透明化 |
| **主動提醒** | 監控清單、從估值自動推導目標價、桌面 + Telegram + email、同日去重 |
| **智慧提醒** | 技術指標（RSI/均線/布林）+ 均價偏離規則引擎、大盤同向判斷、一句話現況摘要、規則回測 |
| **現金流與風險** | 股利（含 NRA 預扣）、波動度、最大回撤、Sharpe、SPY 相關性 |
| **台幣歸因** | 股票漲跌 vs 匯率變動拆解 |

## 兩個前端，一套邏輯

`service.py` 是 CLI 與網頁共用的商業邏輯層。任何一個前端都不直接碰資料庫或行情源。

| 前端 | 狀態 |
|---|---|
| CLI（`stockcapy` / `sc`） | 完成 |
| 網頁（單檔 HTML，無 build step） | 完成 |
| 手機（網頁的 PWA 外殼，加到主畫面） | 完成（Expo Android app 已於 2026-11 移除，見 D25） |

## 明確不做的事

- **不給投資建議**（見原則 1）
- **不做交易執行**——這是判斷工具，下單去券商
- **不做報稅**——成本基礎用移動平均法，與券商報稅用的 FIFO 不同
- **不追求即時報價**——免費行情源約延遲 15 分鐘，對「等到價」的用途足夠
