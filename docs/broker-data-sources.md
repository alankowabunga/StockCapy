# 券商資料來源調查：API、對帳單匯入、AI 解析

調查日期：2026-11-06。**只靠網頁搜尋摘要**，沒讀到各券商登入後的後台，也沒打開官方文件全文
（抓取工具被網路白名單擋住）。「查證程度」欄標明每項結論可信到哪裡，標「未驗證」的請勿當事實。

## 1. 一句話結論

| 問題 | 答案 |
|---|---|
| 美股券商能不能 API 取得持股與交易？ | IB、嘉信、eToro 有官方 API；Firstrade 沒有（只能 CSV） |
| 台灣券商的複委託能不能 API 取得？ | **查不到任何一家**。各家 API 都只涵蓋台股／期貨 |
| 台灣券商要怎麼進資料？ | 對帳單（PDF／Excel）、網頁匯出、手動輸入、通用 CSV |
| 該不該加 AI 解析？ | 該，但當「備援＋開發輔助」，不要當主力（見第 5 節） |

## 2. 美股券商

| 券商 | API | 要登入／授權什麼 | 檔案匯出 | 查證程度 |
|---|---|---|---|---|
| IB 盈透 | **Flex Web Service**：用 token + 查詢 ID 抓報表（`SendRequest` 再 `GetStatement`，建議 `v=3`，限速每秒 1 次、每分鐘 10 次）。另有 Client Portal Web API（需本機 Gateway，要人登入） | 在帳戶管理後台建 Flex Query、產 token。**不用每次登入**，適合排程 | Flex Query 可自選欄位，輸出 CSV／XML。一般 Activity Statement CSV 是多段落格式，不能直接 `read_csv` | Flex 流程：官方文件（搜尋摘要）。Token 有效期摘要寫「預設 6 小時、可調整」，**需對官方確認** |

IB Flex 可用的段落（第三方整理）：Trades、Open Positions、Cash Transactions（股利、預扣稅是**分開的列**）、Dividend Accruals。
台灣居民的預扣稅規則與 IB 台灣實體的報表差異**未查到**。

### 聚合服務（SnapTrade 等）

- SnapTrade 支援 IB、嘉信，eToro 也在其名單內（摘要語意不清）；**Firstrade 未見**；台灣券商不支援。
- 費用：平台費約每月 US$100 起，另有每連線使用者費用；個人 OAuth 使用者目前有 $0 優惠（來源不一致）。
- 不適合 StockCapy：它是自架、不想綁第三方帳號的個人工具，而且覆蓋不到台灣券商。**不建議**。

## 5. AI 解析報表評估

**好處**

- 台灣十家格式未知、可能改版，逐家寫解析器成本高。
- 對帳單常是 PDF，欄位位置不固定，傳統規則容易壞。
- 使用者丟檔案就能用，不必選格式。

**風險**

| 風險 | 說明 | 對策 |
|---|---|---|
| 金額錯誤 | 模型可能漏列、讀錯數字或自行補值；公開資料中**沒有**針對券商對帳單的獨立準確率評測，只有廠商宣稱 | 用對帳單自帶的合計、成交金額＝數量×價格±手續費、與庫存數量比對；失敗就不匯入 |
| 隱私 | 對帳單有姓名、身分證字號、帳號；README 寫「資料存在你自己的機器上」，送雲端模型就違反這個承諾 | 本機先遮罩個資再送出；讓使用者自備 API key 並明確同意；或支援本機模型 |
| 不穩定 | 同一檔案兩次結果可能不同 | 結果一律先預覽，使用者確認才寫入；同一格式確認後存成固定規則 |
| 成本 | 每月一份幾頁，單次約幾分錢量級（**估計，未實測**） | 可接受 |

**建議做法：混合式**

1. **固定格式用規則解析**：Firstrade、IB Flex、通用 CSV，確定、免費、可測試。
2. **開發時用 AI**：你把去識別化的台灣券商樣本丟給我，我寫成固定解析器並加測試。這樣執行時不用 AI，風險最低。**這也是你說的「丟格式給你分析」最有效的用法**。
3. **執行時 AI 只當備援**：遇到不認得的檔案，AI 轉成通用 CSV 格式 → 預覽 → 驗算 → 使用者確認 → 才匯入。不自動寫入。
4. 不要讓 AI 直接改資料庫。

## 6. 建議順序

1. 加 **IB Flex Query CSV** 匯入（格式文件齊全，可立即做）。
2. 你提供 2–3 家常用台灣券商的去識別化樣本，先做這幾家（挑你真的在用的）。
3. 你實測集保 e 手掌握看不看得到複委託；看得到的話優先研究它的匯出格式。
4. 做「AI 備援匯入」：遮罩個資、預覽、驗算、使用者確認。
5. 之後才考慮 IB Flex 自動抓、eToro API。嘉信與聚合服務不做。
